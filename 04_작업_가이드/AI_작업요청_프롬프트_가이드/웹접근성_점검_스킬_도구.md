# 웹접근성 점검 스킬·도구

**이 탭의 용도:** 개발 소스와 실행 화면의 접근성을 진단할 때 Playwright, 자동 검사, 키보드·화면 읽기 도구의 역할을 구분하고 바로 쓸 프롬프트를 복사한다. 설치 상태는 **2026-10-25 이 환경에서 확인한 결과**다.

## 스킬과 점검 기준

Codex 스킬은 AI가 따를 작업 절차(`SKILL.md`)이고, 브라우저·화면 읽기 도구는 실제 조작을 수행하는 수단이다. KWCAG 2.2는 결과를 대조할 기술 기준이다. 현재 환경에서 [Playwright 스킬](https://github.com/openai/skills/tree/main/skills/.curated/playwright)은 **설치 가능한 후보이지만 미설치**다. KWCAG 전용 스킬은 확인되지 않았다. 다른 환경에서는 설치·활성화 여부를 다시 확인한다.

## 접근성 점검에 쓸 수 있는 스킬과 한계

2026-10-25에 확인한 Codex의 설치 가능 스킬 목록에는 **KWCAG 전용 점검 스킬이 없다**. [Playwright 스킬](https://github.com/openai/skills/tree/main/skills/.curated/playwright)은 실제 브라우저에서 탭 이동, 폼 입력, 모달 열기, 오류 상태 등을 재현하고 화면·스냅샷을 남기는 데 사용할 수 있다. 이 스킬은 **현재 설치·활성화된 스킬이 아니라 설치 가능한 후보**이며, 사용 전 현재 환경에서 활성화 여부를 확인해야 한다. 브라우저 자동화 결과만으로 KWCAG 적합성을 판정할 수는 없다.

| 점검 수단 | 맡길 작업 | 사람이 별도로 확인할 것 |
|---|---|---|
| Playwright 스킬(사용 가능할 때) | 실제 사용자 흐름과 상태 전환 재현, 키보드 조작 결과·스크린샷 기록 | 초점 순서의 적절성, 읽기 순서, 대체 문구의 의미, 화면 읽기 도구 사용성 |
| 자동 접근성 검사 도구(프로젝트에 있는 경우) | 실행 환경과 도구 버전을 적고 기계적으로 확인 가능한 결함 수집 | 자동 검사에 잡히지 않는 항목, 오탐·누락, 공식 KWCAG 항목과의 연결 |
| KWCAG 원문 + 수동 검수 | 해당 검사항목 원문에 따라 화면·상태별 실제 사용성 판단 | 운영 주체의 법적 의무와 품질인증은 별도 검토 |

**스킬 요청 문장 예시:** “이 환경에서 사용 가능한 접근성·브라우저 점검 스킬을 먼저 확인해줘. Playwright 스킬이 활성화돼 있으면 해당 `SKILL.md` 절차로 [화면/흐름]의 키보드 조작과 상태 전환을 재현해줘. 없다면 임의로 설치하거나 실행했다고 쓰지 말고, 가능한 코드·화면 검토 범위와 미검증 항목을 구분해줘. KWCAG 2.2 항목은 공식 원문과 대조하고, 자동 검사만으로 적합 판정을 내리지 마.”

## 프롬프트 1. 납품 소스의 웹접근성 진단

**쓸 때:** 개발사가 소스를 납품했거나 기존 서비스를 개편한 뒤, 실제 사용 흐름이 KWCAG 2.2 기준에 맞는지 인수 점검할 때. `[대괄호]`는 실제 경로·버전·테스트 환경으로 바꾼다. 아래 요청은 **진단 전용**이며 수정은 별도 승인 범위로 요청한다.

```text
작업 모드: 읽기·진단만. 납품 소스, 원본 데이터, 승인된 디자인 파일을 수정하지 마.
소스 위치와 커밋/버전: [저장소 경로·커밋 또는 압축 파일 버전]
실행 방법과 테스트 URL: [설치·빌드 문서와 주소]
검토 범위: [화면·공통 컴포넌트·모바일 화면·다운로드 문서]
핵심 사용자 흐름: [예: 로그인 → 신청 → 입력 오류 → 수정 → 제출 → 결과 확인]
기능 정의·승인 디자인: [정확한 문서와 파일 경로]
기술 기준: 한국형 웹 콘텐츠 접근성 지침 KWCAG 2.2(KS X OT0003)

1. 제출된 파일 목록·커밋·의존성·실행 방법을 확인하고, 실행 화면이 그 소스에서 나온 버전인지 밝혀줘.
2. 지금 환경의 설치·활성화된 스킬과 검사 도구를 확인해줘. Playwright 스킬이 있으면 해당 지침에 따라 브라우저 흐름을 재현하고, 없으면 사용했다고 쓰지 마. 자동 검사 도구의 이름·버전·대상 URL도 기록해줘.
3. 화면·상태·공통 컴포넌트를 코드 파일과 연결하고, 의미 요소·제목 구조·대체 텍스트·폼 레이블·오류 안내·명도 대비·상태 전달·동적 콘텐츠 안내를 점검해줘.
4. 키보드만 사용해 처음부터 완료까지 Tab/Shift+Tab, Enter/Space, Esc를 시도하고 초점 순서·표시·이동·복귀를 기록해줘. 탭, 아코디언, 모달, 달력, 오류·빈 결과·완료 상태도 포함해줘.
5. 화면 읽기 도구를 사용할 수 있으면 도구·브라우저·버전을 적고 요소의 이름·역할·상태·읽기 순서를 확인해줘. 사용할 수 없다면 해당 항목은 미검증으로 남겨줘.
6. 좁은 화면과 글자 확대 상태에서 내용 가림·겹침·가로 스크롤을 확인해줘. 색만으로 구분하는 정보와 이미지·아이콘의 대체 설명도 실제 의미와 대조해줘.
7. 각 결함을 공식 KWCAG 2.2 검사항목의 정확한 명칭·번호와 연결해줘. WCAG 2.2 번호를 KWCAG 번호처럼 쓰지 마. 원문을 확인하지 못했다면 항목 번호는 추정하지 마.
8. 자동 검사 통과를 전체 적합 판정으로 쓰지 말고, 실행하지 못한 흐름·접근 권한 부족·테스트 데이터 부족을 모두 명시해줘.

결과 표: 화면·상태 | 재현 순서 | 기대 동작/실제 동작 | 사용자 영향 |
KWCAG 항목 | 소스 파일·줄 번호 | 증거(실행/자동/수동/코드 추정) |
심각도 | 수정 제안 | 재검증 방법.
끝에 핵심 흐름 사용 가능 여부, 확인된 결함 수, 미검증 범위, 인수 전 우선 수정 항목을 요약해줘.
법적 의무 이행과 품질인증 취득 여부는 이 진단만으로 확정하지 마.
```

## 진단 결과를 읽는 법

자동 검사 결과, 키보드로 직접 재현한 결과, 화면 읽기 도구 확인 결과, 소스 코드만 보고 추정한 내용을 각각 표시한다. 실행하지 못한 상태는 **미검증**으로 남긴다. 법적 의무와 품질인증 여부는 [웹접근성 법령·기준](웹접근성_법령_기준.md)을 따로 확인한다.
