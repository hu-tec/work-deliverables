# 보안 점검 스킬·도구

**이 탭의 용도:** 받은 소스의 보안 코드 검토와 위협 모델링을 구분하고, 개인정보·자격증 발급 흐름에 맞는 진단 프롬프트를 사용한다. 설치 상태는 **2026-10-25 이 환경에서 확인한 결과**다.

## 스킬과 도구의 역할

Codex 스킬은 점검 절차를 제공하지만 그 자체가 취약점 스캐너나 침투 시험 결과는 아니다. [security-best-practices](https://github.com/openai/skills/tree/main/skills/.curated/security-best-practices)와 [security-threat-model](https://github.com/openai/skills/tree/main/skills/.curated/security-threat-model)은 **설치 가능한 후보이며 현재 환경에서는 미설치**다. 다른 환경에서는 활성화 여부를 다시 확인한다.

## 보안 코드 검토: security-best-practices

[공식 스킬](https://github.com/openai/skills/tree/main/skills/.curated/security-best-practices)은 저장소에서 사용 언어와 프레임워크를 확인한 뒤 해당 보안 지침에 비추어 코드를 검토한다. **Python·JavaScript/TypeScript·Go** 범위를 우선 지원한다. 자격증 발급 시스템이라면 본인확인 응답 검증, 권한 확인, 개인정보 로그 노출, 비밀값 관리, 다운로드 접근을 실제 코드 위치와 연결해 요청한다.

입력으로 **소스 경로·커밋, 사용 환경, 개인정보 처리 흐름, 검토 범위**를 제공한다. 결과에서는 **파일·줄 번호, 영향, 심각도, 실제 재현 여부, 수정 제안**을 받아야 한다. 이 스킬은 침투 시험이나 법적 적합성 판정을 대체하지 않는다.

## 공격 경로 정리: security-threat-model

[공식 스킬](https://github.com/openai/skills/tree/main/skills/.curated/security-threat-model)은 저장소 근거로 구성 요소와 데이터 자산을 찾고, **신뢰 경계와 공격·남용 경로**를 정리한다. 예를 들어 “본인확인 결과 재사용 → 타인 자격증 발급”이나 “추측 가능한 발급번호 → 타인 증명서 조회” 같은 경로를 기존 방어책과 함께 검토한다. 명시적으로 위협 모델링을 요청할 때 쓰는 스킬이다.

입력으로 **배포 방식, 인터넷 노출, 인증·권한, 본인확인기관 연결, 저장 데이터**를 제공한다. 결과에서는 **확인된 구조와 가정, 공격자 목표, 기존 통제와 제안 통제**를 구분한다. 서비스 맥락이 없으면 위험도 판단이 달라질 수 있으므로 미확인 질문을 남긴다.

## 보안 스킬 사용 조건과 요청 예시

| 요청 목적 | 적용할 스킬(활성화된 경우) | 검토 결과에 남길 증거 |
|---|---|---|
| 소스의 보안 기본값·취약한 패턴 검토 | `security-best-practices` | 언어/프레임워크, 실제 참고한 스킬 지침, 파일·줄 번호, 재현 가능성 |
| 본인확인·발급·조회·저장 흐름의 위협 모델링 | `security-threat-model` | 구성 요소, 개인정보 자산, 신뢰 경계, 공격 경로, 기존 통제와 미확인 가정 |

**스킬 요청 문장 예시:** “먼저 이 환경의 설치·활성화된 스킬을 확인해줘. `security-best-practices`가 있으면 실제 사용 언어·프레임워크에 해당하는 지침으로 [경로]를 검토해줘. `security-threat-model`이 있으면 본인확인 → 자격 확인 → 발급 → 진위조회 경로의 자산·신뢰 경계·남용 경로를 저장소 근거로 정리해줘. 없거나 지원 범위 밖이면 그렇게 적고 일반 코드 검토로 계속해줘. 법령 적용 판단과 실제 공격 재현 여부는 별도 열로 보고해줘.”

## 프롬프트 1. 납품 소스의 보안 진단

**쓸 때:** 자격증 발급·본인확인 시스템의 소스, DB 스키마, 배포 설정을 받은 뒤 개인정보 처리와 권한 통제를 검토할 때. 실제 개인정보 대신 합성 데이터로 재현한다.

```text
작업 모드: 읽기·진단만. 소스, DB, 운영 설정을 수정하거나 실제 개인정보·비밀값을 출력하지 마.
대상 저장소와 커밋/버전: [정확한 경로·해시]
실행·배포 구성: [개발/테스트/운영 구조와 문서]
검토 흐름: [본인확인 → 자격 확인 → 발급 → 다운로드 → 진위조회 → 파기]
승인 기준: [기능 정의, 개인정보 처리방침, 보유기간, 권한표, 본인확인 연동 규격]

1. 사용 언어·프레임워크, 서버·DB·파일 저장소·외부 연동을 소스 근거로 파악해줘.
2. 설치·활성화된 보안 스킬을 확인해줘. security-best-practices가 지원하는 언어·프레임워크라면 해당 지침으로 코드 검토를 해줘. security-threat-model이 있으면 데이터 자산, 신뢰 경계, 공격·남용 경로를 저장소 근거로 정리해줘. 없으면 사용했다고 쓰지 마.
3. 인증 응답 위조·재사용, 타인 증명서 접근, 발급번호 추측, 관리자 권한 남용, 대량 조회·다운로드, 비밀값 노출을 살펴줘.
4. 주민등록번호·CI/DI·인증 응답·증명서 PDF가 입력, 전송, DB, 로그, URL, 캐시, 백업 어디에 남는지 값 자체를 출력하지 말고 필드·파일·흐름으로 보고해줘.
5. 접근 제어, 입력 검증, 세션·토큰 만료, 암호화·키 관리, 로그 마스킹, 파기 작업과 백업 복원 후 처리의 구현 증거를 찾아줘.
6. 허용된 테스트 환경과 합성 데이터로만 재현하고, 실행하지 못한 항목은 코드상 추정 또는 미검증으로 구분해줘.

결과 표: 위험 항목 | 사용자·정보 영향 | 재현 단계 또는 코드 근거 | 파일·줄 번호 |
확인 방식(실행/도구/코드 추정/미검증) | 심각도·이유 | 수정 제안 | 재검증 방법.
끝에 즉시 수정할 항목, 운영 정책 확인이 필요한 항목, 실행하지 못한 검사를 구분해줘.
기술 검토만으로 법적 적합성이나 인증 취득 여부를 확정하지 마.
```

## 결과를 읽는 법

스킬 사용 여부와 적용한 지침, 검사 도구·버전, 코드 위치, 재현 가능한 공격 경로를 함께 확인한다. 실제 취약점과 설정·운영 가정을 분리한다. 법적 적용 범위는 [개인정보·보안 법령·기준](개인정보_보안_법령_기준.md)을 따로 검토한다.
