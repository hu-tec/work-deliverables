# 웹접근성 법령·기준

**이 탭의 용도:** 장애인차별금지법과 디지털포용법의 적용 범위를 확인하고, KWCAG 2.2 기술 점검과 품질인증을 구분한다. **2026-10-25 확인 기준**이며 실제 서비스의 운영 주체와 적용 시점에 맞춰 현행 원문을 다시 확인한다.

## 먼저 구분할 네 가지

| 구분 | 뜻 | 검토 결과에 적을 것 |
|---|---|---|
| 법률·시행령 | 누가 어떤 의무를 지는지 정하는 규범 | 적용 조항·시행일·운영 주체 해당 여부와 근거 |
| 고시·국가표준 | 안전조치나 접근성의 세부 기준 | 적용 검사항목과 실제 재현 증거 |
| 품질·관리체계 인증 | 별도 신청·심사 또는 일정 요건 충족 시 의무 | 기술 점검 결과와 인증 상태를 따로 기록 |
| 서비스 내부 규칙 | 자격증 발급 조건, 보유기간, 계약상 역할 | 확정 문서의 버전과 미결정 책임자 |

## 국내 법령·기술 기준을 구분해서 보기

법률은 **누가 어떤 접근을 보장해야 하는지**, 시행령은 **대상과 편의의 구체적 내용**, KWCAG는 **화면을 어떻게 점검할지**를 다룬다. 기술 검사를 통과했다고 법적 의무가 자동으로 끝나는 것은 아니며, 법적 의무가 적용된다고 품질인증을 반드시 신청해야 한다는 뜻도 아니다.

| 자료 | 확인된 핵심 내용 | 이 프로젝트에서 할 일 |
|---|---|---|
| [장애인차별금지법 제21조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031812007) | 해당 조문의 행위자 등이 생산·배포하는 정보와 정보통신 서비스에 장애인이 동등하게 접근·이용하도록 필요한 수단·정당한 편의를 제공 | 운영 주체와 제공 서비스가 해당 행위자 범위에 드는지 확인 |
| [같은 법 시행령 제14조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1030492419) | 법 제21조의 단계적 적용 범위와 편의 내용을 구체화하고, 접근성이 보장되는 웹사이트를 필요한 수단으로 규정 | 적용 대상은 시행령과 별표까지 대조하고 실제 사용자 흐름을 점검 |
| [디지털포용법 제19조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031811025) | 국가기관등이 제공하는 웹사이트 등의 접근성 보장 의무와 지능정보사업자의 접근·이용 편의 노력 규정을 구분 | 공공·민간 여부와 서비스 성격에 따라 해당 항을 구분해 판단 |
| [디지털포용법 제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031811029) | 접근성 **품질인증 제도**의 근거 | 기술 점검, 법적 의무, 품질인증 신청·취득을 별도 상태로 기록 |
| [KWCAG 2.2 국가표준](https://www.rra.go.kr/ko/reference/kcsList_view.do?nb_seq=5247&nb_type=6) | 화면을 점검할 때 쓰는 국내 기술 기준 | 실제 검사항목의 명칭·번호와 재현 증거를 연결 |

**옛 법령 인용 주의:** 과거 안내에는 `지능정보화 기본법 제46·47조`가 등장하지만 현행 해당 조문은 삭제되었다. 현재 접근성 보장·품질인증 규정은 위의 디지털포용법 제19·21조를 확인한다. [제46조 삭제](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1027603357) · [제47조 삭제](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0047&lsiSeq=268535&urlMode=lsScJoRltInfoR)

이 표는 **2026-10-25 확인 기준**이다. 실제 프로젝트의 의무 범위는 운영 기관, 서비스 유형, 적용 시점과 시행령 별표를 법무·접근성 담당자가 검토한다.

## 국내 기준: KWCAG 2.2를 먼저 확인

**KWCAG**는 ‘한국형 웹 콘텐츠 접근성 지침’이다. 국립전파연구원 자료실에는 **KWCAG 2.2, KS X OT0003(2022-12-28 개정)**이 ‘유지’ 상태로 게시되어 있다. 국내 웹 화면을 점검할 때 먼저 이 표준의 적용 검사항목을 확인하고, 국제 지침인 WCAG 2.2는 보완 참고 자료로 구분한다. KWCAG와 WCAG는 이름과 번호가 같지 않으므로 **WCAG 번호를 KWCAG 번호로 그대로 옮겨 쓰지 않는다**. [국립전파연구원 표준 자료](https://www.rra.go.kr/ko/reference/kcsList_view.do?nb_seq=5247&nb_type=6)

KWCAG는 **인식의 용이성, 운용의 용이성, 이해의 용이성, 견고성**의 네 원칙으로 이해하면 쉽다. 화면과 기능에서 대체 텍스트·명도 대비·키보드 조작·명확한 레이블·오류 안내·보조기술과의 호환 등을 확인한다. 2.2 개정에는 문자 단축키, 고정된 참조 위치, 단일 포인터 입력·취소, 레이블과 네임, 동작 기반 작동, 찾기 쉬운 도움, 접근 가능한 인증, 반복 입력 정보 등 **9개 검사항목**이 추가되었다. [NIA 개정 설명](https://www.nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=25083&cbIdx=90549)

| 구분 | 이 가이드에서의 역할 | 결과에 적는 방법 |
|---|---|---|
| KWCAG 2.2 | 국내 화면 점검의 우선 기술 기준 | 해당 검사항목의 명칭·번호·실제 위반 근거를 기록 |
| WCAG 2.2 | 국제 기준과 추가 참고 | KWCAG와 별도 열에 적고 동일 기준이라고 단정하지 않음 |
| 법적 의무·품질인증 | 적용 대상과 인증 범위는 서비스·기관별로 확인 | 법적 적용 여부·인증 결과를 코드 점검만으로 단정하지 않음 |

네 원칙을 실제 화면으로 옮기면 **인식의 용이성**은 이미지·영상·색을 볼 수 없어도 정보를 알 수 있는지, **운용의 용이성**은 마우스 없이 이동·선택·제출할 수 있는지, **이해의 용이성**은 입력 목적과 오류·다음 행동을 알 수 있는지, **견고성**은 화면 읽기 도구 등 보조기술이 요소의 이름·역할·상태를 해석할 수 있는지를 묻는 것이다. 이 설명은 원칙의 실무적 해석이며, 적합 판정은 표준의 개별 검사항목으로 수행한다.

## 화면에서 확인할 웹접근성 기준

KWCAG 2.2는 **4개 원칙과 33개 검사항목**으로 구성된다. 아래 표는 개발·검수 때 놓치기 쉬운 내용을 화면 행동으로 풀어쓴 **실무 요약**이다. 전체 항목의 정확한 이름·번호·예외는 [국립전파연구원 국가표준 원문](https://www.rra.go.kr/ko/reference/kcsList_view.do?nb_seq=5247&nb_type=6)에서 확인한다. [웹접근성 품질인증기관의 33개 심사 항목](https://www.wa.or.kr/m1/sub3.asp)은 인증 심사용 목록이다. 인증 심사 방식이나 합격 기준을 일반 소스 점검 결과에 그대로 적용하지 않는다.

| 원칙 | 항목 수 | 빠르게 확인할 범위 |
|---|---:|---|
| 인식의 용이성 | 9 | 비문자 정보·영상, 표와 읽기 순서, 감각에만 의존하지 않는 안내, 색·대비·소리·콘텐츠 구분 |
| 운용의 용이성 | 15 | 키보드·초점·조작, 시간과 움직임, 건너뛰기·제목·링크, 단축키·포인터·확대 시 위치 |
| 이해의 용이성 | 7 | 기본 언어와 예측 가능한 동작, 도움말, 입력 레이블·오류, 인증과 반복 입력 |
| 견고성 | 2 | 마크업 구조, 보조기술이 해석하는 웹 애플리케이션 상태 |

항목 수와 범위는 [품질인증기관의 공개 심사 목록](https://www.wa.or.kr/m1/sub3.asp)을 네 원칙으로 묶은 안내다. 목록의 순번은 KWCAG 원문 검사항목 번호와 다르므로, 결함 보고서에는 반드시 국가표준의 번호와 명칭을 다시 확인해 적는다.

| 원칙 | 화면·기능에서 확인할 기준 | 재현할 상태와 증거 |
|---|---|---|
| 인식의 용이성 | 의미 있는 이미지·아이콘·차트의 대체 설명, 영상의 자막 등 대체수단, 표의 행·열 관계, 논리적인 읽기 순서 | 이미지를 읽지 않을 때도 같은 의미가 전달되는지, 화면 읽기 도구가 표를 이해할 수 있는지 |
| 인식의 용이성 | 색만으로 상태를 구분하지 않기, 텍스트와 배경의 명도 대비, 이웃 콘텐츠의 구분, 예기치 않은 소리 자동 재생 방지 | 오류·선택·필수 항목을 흑백/고대비 상태에서도 구별하는지, 대비 측정값과 예외 근거 |
| 운용의 용이성 | 모든 핵심 기능의 키보드 조작, 논리적인 초점 이동과 보이는 초점, 조작할 수 있는 컨트롤 | Tab·Shift+Tab·Enter·Space·Esc만으로 메뉴·탭·대화상자·폼을 완료하는 기록 |
| 운용의 용이성 | 반복 영역 건너뛰기, 적절한 제목·링크 목적, 시간 제한 조절, 움직임 정지와 깜빡임 제한 | 첫 초점부터 본문 이동, 세션 만료·자동 전환·배너 정지, 링크만 읽을 때 목적 파악 |
| 운용의 용이성 | 터치·포인터 동작을 대체할 방법과 취소 가능성, 화면 확대 중 참조 위치 유지 | 한 손가락·단일 포인터, 확대 후 메뉴·입력·제출 흐름의 사용 가능 여부 |
| 이해의 용이성 | 기본 언어, 예측 가능한 화면 변화, 찾기 쉬운 도움, 입력 항목의 명확한 레이블과 오류 수정 안내 | 필수값 누락·형식 오류·제출 완료 상태에서 문제와 다음 행동을 알 수 있는지 |
| 이해의 용이성 | 접근 가능한 인증 방식과 이미 입력한 정보의 불필요한 재입력 방지 | 로그인·본인확인·신청 단계에서 기억·인지에만 의존하지 않고 완료할 수 있는지 |
| 견고성 | 올바른 마크업과 사용자 정의 컨트롤의 이름·역할·상태 전달 | 화면 읽기 도구에서 버튼·탭·펼침 상태가 실제 동작과 일치하는지 |

**2.2에서 추가된 9개 항목의 확인 지점:** 문자 단축키 오작동(6.1.4), 확대 시 참조 위치 유지(6.4.4), 단일 포인터 사용(6.5.1), 포인터 입력 취소(6.5.2), 화면에 보이는 레이블과 접근 가능한 이름(6.5.3), 움직임 기반 조작의 대안(6.5.4), 도움 정보의 위치(7.2.2), 접근 가능한 인증(7.3.3), 반복 입력 정보(7.3.4)를 확인한다. 항목 번호와 명칭은 [NIA 개정 설명](https://www.nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=25083&cbIdx=90549)에 게시되어 있으며, 실제 판정에는 국가표준 원문의 적용 조건과 예외를 대조한다.

점검 결과는 화면·상태·사용자 흐름마다 **충족 / 결함 확인 / 해당 없음과 이유 / 미검증과 이유**로 기록한다. 자동 검사에서 경고가 없다는 사실만으로 실제 키보드·보조기술 사용성을 충족했다고 판단하지 않는다. 민원이 접수된 화면은 같은 버전·환경의 재현 결과와 현재 버전의 결과를 별도로 남긴다.

## 프롬프트 1. 서비스별 웹접근성 법령 적용 범위 확인

```text

판단 기준일: [YYYY-MM-DD]
운영 주체: [법적 명칭, 공공기관/민간사업자/교육기관 등]

이용자 흐름과 기능: [로그인·신청·결제·증명서 다운로드 등]

국가법령정보센터에서 판단 기준일에 시행 중인 원문을 확인하고 다음을 분리해줘.
1. 장애인차별금지법 제21조와 시행령 제14조·별표의 해당 행위자·서비스·편의 범위
2. 디지털포용법 제19조의 국가기관등 의무와 지능정보사업자 노력 규정 중 실제 해당 부분
3. KWCAG 2.2 기술 점검 기준과 디지털포용법 제21조의 품질인증 제도
4. 옛 지능정보화 기본법 제46·47조를 현행 근거로 잘못 인용한 문서가 있는지

결과 표: 조항·기준 | 시행일·공식 URL | 적용 대상 | 이 서비스 해당 여부·근거 |
필요한 편의·점검 항목 | 확인할 화면·문서 | 미확인 사실 | 결정 담당자.
운영 주체나 적용 범위가 불명확하면 '판단 보류'로 적어줘.
기술적 결함, 법적 의무 이행, 품질인증 취득을 하나의 결론으로 합치지 마.
```

## 프롬프트 2. 개발 소스와 화면의 근거 매핑

```text
작업 모드: 점검 대상은 읽기만. 보고서 HTML 파일만 새로 작성해줘.
대상 소스·커밋과 실행 URL: [정확한 값]
운영 주체의 법령 적용 검토 결과: [승인 문서 경로]
점검할 화면·상태: [목록]
HTML 보고서 저장 경로: [예: reports/접근성_법령_기준_검토.html]

법령상 적용 범위와 KWCAG 2.2 기술 검사항목을 먼저 구분해줘.
각 화면·상태를 실제 조작한 증거, 자동 검사 결과, 코드 위치와 연결해줘.
검사항목의 정확한 명칭·번호는 공식 KWCAG 원문과 대조하고 WCAG 번호를 그대로 옮기지 마.
실행하지 못한 흐름과 보조기술 검사는 미검증으로 표시해줘.
결과를 적용 근거·증거·결함·미검증·담당자 결정 항목이 분리된 한국어 HTML 보고서로 저장해줘.
기술 검사 결과만으로 법적 적합성이나 품질인증을 확정하지 마.
```

## 프롬프트 3. 웹접근성 민원 발생 시 법령·기준과 답변 근거 확인

**쓸 때:** 민원 대응 담당자가 기술 진단 결과를 받아 적용 근거와 답변 내용을 검토할 때. 실제 진단·수정 요청문은 [웹접근성 프롬프트 8](웹접근성_프롬프트.md)을 사용한다.

```text
작업 모드: 읽기·검토만. 사이트·민원 원본·운영 기록을 수정하거나 답변을 발송하지 마.
민원 접수일·답변 기한·운영 주체: [확인된 값, 없으면 미확인]
민원 내용과 대상 기능: [개인정보를 제거한 요지·URL·사용 흐름]
문제 발생 시점의 버전·현재 버전: [배포 기록·커밋]
기술 진단·수정·재검증 보고서: [정확한 경로]
기관의 민원 처리 규정·계약: [승인된 문서 경로, 없으면 미확인]

민원 접수일과 현재 시점 각각의 국가법령정보센터 시행 원문을 확인하고, 장애인차별금지법 제21조·시행령 제14조 및 별표, 디지털포용법 제19조 중 이 운영 주체와 서비스에 해당할 수 있는 부분을 근거와 함께 정리해줘.
기술 진단의 KWCAG 2.2 검사항목은 공식 표준의 명칭·번호와 대조하고, 민원 주장·확인된 결함·재현 실패·미검증을 구분해줘.
민원 처리 기한이나 법적 의무 범위를 추측하지 말고, 해당 기관 규정·계약·법무 검토가 필요한 부분을 담당자 질문으로 남겨줘.
결과 표: 민원 쟁점 | 실제 증거·버전 | 기술 기준 | 법령 적용 가능성·공식 URL | 완료한 조치 | 남은 조치·기한 근거 | 결정 담당자.
민원 답변 초안은 확인된 사실, 이용에 미친 영향, 수정·재검증 결과, 남은 조치와 연락 경로만 담아줘. 법적 위반 또는 완전 적합을 기술 검사 결과만으로 확정하지 마. 민원인의 개인정보나 민감한 사용 환경을 초안에 불필요하게 옮기지 마.
```

## 프롬프트 4. KWCAG 기준별 화면 점검표 만들기

```text
작업 모드: 읽기·점검만. 소스·디자인·운영 데이터는 수정하지 마.
대상 서비스·소스 버전·실행 URL: [정확한 값]
점검할 화면과 상태: [기본·키보드 초점·오류·팝업·완료·모바일·확대 등]
핵심 사용자 흐름: [예: 메뉴 → 신청 → 인증 → 제출 → 결과 확인]
기술 기준: 국립전파연구원 KWCAG 2.2(KS X OT0003) 원문

KWCAG 2.2의 전체 검사항목을 공식 원문에서 확인하고, 각 항목이 이 서비스의 어떤 화면·상태·공통 컴포넌트에 관련되는지 범위표를 만들어줘.
해당하지 않는 항목은 이유를 적고, 확인하지 못한 항목을 통과로 표시하지 마.
각 대상은 자동 검사, 키보드 직접 조작, 가능할 때 화면 읽기 도구·확대 화면 점검의 결과를 구분해줘.
결과 표: 원칙 | 공식 항목 번호·명칭 | 화면·상태 | 재현 단계 | 기대/실제 | 증거·도구 | 충족/결함/해당 없음/미검증 | 수정·재검증 방법.
민원이 있는 항목은 접수 당시 버전과 현재 버전의 증거를 따로 적고, 다른 화면의 같은 컴포넌트에도 영향이 있는지 확인해줘.
WCAG 2.2는 필요한 경우 별도 참고 열에만 쓰고 KWCAG 번호와 섞지 마. 법적 적합성이나 품질인증 취득 여부를 이 표만으로 확정하지 마.
```
