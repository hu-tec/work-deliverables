# 점검 스킬·도구: 무엇을 맡기고 어떻게 확인할까

**이 탭의 용도:** 개발 소스를 받은 뒤 웹접근성·보안을 검토할 때, 사용할 수 있는 Codex 스킬과 일반 도구의 역할을 구분한다. 아래 설치 상태는 **2026-10-25 이 환경에서 확인한 결과**이며 다른 작업 환경에서는 다시 확인한다.

## 스킬과 도구의 차이

Codex **스킬**은 특정 작업의 절차를 적은 `SKILL.md` 지침이다. 설치 가능 목록에 보이는 것과 현재 작업에서 활성화된 것은 다르다. **도구**는 브라우저 자동화, 정적 분석, 화면 읽기 프로그램처럼 실제 검사를 수행하는 수단이다. **법령·KWCAG 원문**은 판단 기준이다. 스킬이나 자동 도구를 사용했다는 사실만으로 보안 안전성 또는 접근성 적합성이 증명되지는 않는다.

| 목적 | 먼저 확인할 것 | 결과물 |
|---|---|---|
| 접근성 흐름 재현 | 실행 URL, 테스트 계정, 화면·상태 목록, 브라우저 실행 가능 여부 | 키보드 조작·초점·상태 전환의 실제 재현 기록 |
| 보안 코드 검토 | 저장소 버전, 언어·프레임워크, 처리 데이터, 검토 범위 | 파일·줄 번호와 영향이 있는 우선순위별 발견 사항 |
| 위협 모델링 | 배포 방식, 인증·권한 구조, 외부 연동, 개인정보 흐름 | 자산·신뢰 경계·남용 경로·기존 통제·미확인 가정 |

## 이 환경에서 확인한 스킬

| 스킬 | 현재 상태 | 맡길 작업 | 결과를 오해하지 않으려면 |
|---|---|---|---|
| [Playwright](https://github.com/openai/skills/tree/main/skills/.curated/playwright) | 설치 가능, 현재 미설치 | 브라우저 화면·키보드 흐름 재현 | KWCAG 전체 합격 판정은 별도 |
| [security-best-practices](https://github.com/openai/skills/tree/main/skills/.curated/security-best-practices) | 설치 가능, 현재 미설치 | 지원 언어·프레임워크의 보안 코드 검토 | 법령 적용·실제 침투 시험과 구분 |
| [security-threat-model](https://github.com/openai/skills/tree/main/skills/.curated/security-threat-model) | 설치 가능, 현재 미설치 | 데이터 흐름·신뢰 경계·공격 경로 분석 | 미확인 운영 조건을 가정으로 표시 |

KWCAG에 특화된 설치 가능 스킬은 확인되지 않았다. 위 상태는 이 작업 환경을 확인한 시점의 결과이며, 복사한 프롬프트를 다른 환경에서 실행할 때는 다시 확인해야 한다.

## 접근성 점검에 쓸 수 있는 스킬과 한계

2026-10-25에 확인한 Codex의 설치 가능 스킬 목록에는 **KWCAG 전용 점검 스킬이 없다**. [Playwright 스킬](https://github.com/openai/skills/tree/main/skills/.curated/playwright)은 실제 브라우저에서 탭 이동, 폼 입력, 모달 열기, 오류 상태 등을 재현하고 화면·스냅샷을 남기는 데 사용할 수 있다. 이 스킬은 **현재 설치·활성화된 스킬이 아니라 설치 가능한 후보**이며, 사용 전 현재 환경에서 활성화 여부를 확인해야 한다. 브라우저 자동화 결과만으로 KWCAG 적합성을 판정할 수는 없다.

| 점검 수단 | 맡길 작업 | 사람이 별도로 확인할 것 |
|---|---|---|
| Playwright 스킬(사용 가능할 때) | 실제 사용자 흐름과 상태 전환 재현, 키보드 조작 결과·스크린샷 기록 | 초점 순서의 적절성, 읽기 순서, 대체 문구의 의미, 화면 읽기 도구 사용성 |
| 자동 접근성 검사 도구(프로젝트에 있는 경우) | 실행 환경과 도구 버전을 적고 기계적으로 확인 가능한 결함 수집 | 자동 검사에 잡히지 않는 항목, 오탐·누락, 공식 KWCAG 항목과의 연결 |
| KWCAG 원문 + 수동 검수 | 해당 검사항목 원문에 따라 화면·상태별 실제 사용성 판단 | 운영 주체의 법적 의무와 품질인증은 별도 검토 |

**스킬 요청 문장 예시:** “이 환경에서 사용 가능한 접근성·브라우저 점검 스킬을 먼저 확인해줘. Playwright 스킬이 활성화돼 있으면 해당 `SKILL.md` 절차로 [화면/흐름]의 키보드 조작과 상태 전환을 재현해줘. 없다면 임의로 설치하거나 실행했다고 쓰지 말고, 가능한 코드·화면 검토 범위와 미검증 항목을 구분해줘. KWCAG 2.2 항목은 공식 원문과 대조하고, 자동 검사만으로 적합 판정을 내리지 마.”

## 프롬프트 1. 납품 소스의 웹접근성 진단

**쓸 때:** 개발사가 소스를 납품했거나 기존 서비스를 개편한 뒤, 실제 사용 흐름이 KWCAG 2.2 기준에 맞는지 인수 점검할 때. `[대괄호]`는 실제 경로·버전·테스트 환경으로 바꾼다. 아래 요청은 **진단 전용**이며 수정은 별도 승인 범위로 요청한다.

```text
작업 모드: 읽기·진단만. 납품 소스, 원본 데이터, 승인된 디자인 파일을 수정하지 마.
소스 위치와 커밋/버전: [저장소 경로·커밋 또는 압축 파일 버전]
실행 방법과 테스트 URL: [설치·빌드 문서와 주소]
검토 범위: [화면·공통 컴포넌트·모바일 화면·다운로드 문서]
핵심 사용자 흐름: [예: 로그인 → 신청 → 입력 오류 → 수정 → 제출 → 결과 확인]
기능 정의·승인 디자인: [정확한 문서와 파일 경로]
기술 기준: 한국형 웹 콘텐츠 접근성 지침 KWCAG 2.2(KS X OT0003)

1. 제출된 파일 목록·커밋·의존성·실행 방법을 확인하고, 실행 화면이 그 소스에서 나온 버전인지 밝혀줘.
2. 지금 환경의 설치·활성화된 스킬과 검사 도구를 확인해줘. Playwright 스킬이 있으면 해당 지침에 따라 브라우저 흐름을 재현하고, 없으면 사용했다고 쓰지 마. 자동 검사 도구의 이름·버전·대상 URL도 기록해줘.
3. 화면·상태·공통 컴포넌트를 코드 파일과 연결하고, 의미 요소·제목 구조·대체 텍스트·폼 레이블·오류 안내·명도 대비·상태 전달·동적 콘텐츠 안내를 점검해줘.
4. 키보드만 사용해 처음부터 완료까지 Tab/Shift+Tab, Enter/Space, Esc를 시도하고 초점 순서·표시·이동·복귀를 기록해줘. 탭, 아코디언, 모달, 달력, 오류·빈 결과·완료 상태도 포함해줘.
5. 화면 읽기 도구를 사용할 수 있으면 도구·브라우저·버전을 적고 요소의 이름·역할·상태·읽기 순서를 확인해줘. 사용할 수 없다면 해당 항목은 미검증으로 남겨줘.
6. 좁은 화면과 글자 확대 상태에서 내용 가림·겹침·가로 스크롤을 확인해줘. 색만으로 구분하는 정보와 이미지·아이콘의 대체 설명도 실제 의미와 대조해줘.
7. 각 결함을 공식 KWCAG 2.2 검사항목의 정확한 명칭·번호와 연결해줘. WCAG 2.2 번호를 KWCAG 번호처럼 쓰지 마. 원문을 확인하지 못했다면 항목 번호는 추정하지 마.
8. 자동 검사 통과를 전체 적합 판정으로 쓰지 말고, 실행하지 못한 흐름·접근 권한 부족·테스트 데이터 부족을 모두 명시해줘.

결과 표: 화면·상태 | 재현 순서 | 기대 동작/실제 동작 | 사용자 영향 |
KWCAG 항목 | 소스 파일·줄 번호 | 증거(실행/자동/수동/코드 추정) |
심각도 | 수정 제안 | 재검증 방법.
끝에 핵심 흐름 사용 가능 여부, 확인된 결함 수, 미검증 범위, 인수 전 우선 수정 항목을 요약해줘.
법적 의무 이행과 품질인증 취득 여부는 이 진단만으로 확정하지 마.
```

## 보안 코드 검토: security-best-practices

[공식 스킬](https://github.com/openai/skills/tree/main/skills/.curated/security-best-practices)은 저장소에서 사용 언어와 프레임워크를 확인한 뒤 해당 보안 지침에 비추어 코드를 검토한다. **Python·JavaScript/TypeScript·Go** 범위를 우선 지원한다. 자격증 발급 시스템이라면 본인확인 응답 검증, 권한 확인, 개인정보 로그 노출, 비밀값 관리, 다운로드 접근을 실제 코드 위치와 연결해 요청한다.

입력으로 **소스 경로·커밋, 사용 환경, 개인정보 처리 흐름, 검토 범위**를 제공한다. 결과에서는 **파일·줄 번호, 영향, 심각도, 실제 재현 여부, 수정 제안**을 받아야 한다. 이 스킬은 침투 시험이나 법적 적합성 판정을 대체하지 않는다.

## 공격 경로 정리: security-threat-model

[공식 스킬](https://github.com/openai/skills/tree/main/skills/.curated/security-threat-model)은 저장소 근거로 구성 요소와 데이터 자산을 찾고, **신뢰 경계와 공격·남용 경로**를 정리한다. 예를 들어 “본인확인 결과 재사용 → 타인 자격증 발급”이나 “추측 가능한 발급번호 → 타인 증명서 조회” 같은 경로를 기존 방어책과 함께 검토한다. 명시적으로 위협 모델링을 요청할 때 쓰는 스킬이다.

입력으로 **배포 방식, 인터넷 노출, 인증·권한, 본인확인기관 연결, 저장 데이터**를 제공한다. 결과에서는 **확인된 구조와 가정, 공격자 목표, 기존 통제와 제안 통제**를 구분한다. 서비스 맥락이 없으면 위험도 판단이 달라질 수 있으므로 미확인 질문을 남긴다.

## 보안 스킬 사용 조건과 요청 예시

| 요청 목적 | 적용할 스킬(활성화된 경우) | 검토 결과에 남길 증거 |
|---|---|---|
| 소스의 보안 기본값·취약한 패턴 검토 | `security-best-practices` | 언어/프레임워크, 실제 참고한 스킬 지침, 파일·줄 번호, 재현 가능성 |
| 본인확인·발급·조회·저장 흐름의 위협 모델링 | `security-threat-model` | 구성 요소, 개인정보 자산, 신뢰 경계, 공격 경로, 기존 통제와 미확인 가정 |

**스킬 요청 문장 예시:** “먼저 이 환경의 설치·활성화된 스킬을 확인해줘. `security-best-practices`가 있으면 실제 사용 언어·프레임워크에 해당하는 지침으로 [경로]를 검토해줘. `security-threat-model`이 있으면 본인확인 → 자격 확인 → 발급 → 진위조회 경로의 자산·신뢰 경계·남용 경로를 저장소 근거로 정리해줘. 없거나 지원 범위 밖이면 그렇게 적고 일반 코드 검토로 계속해줘. 법령 적용 판단과 실제 공격 재현 여부는 별도 열로 보고해줘.”

## 점검 순서와 결과 읽는 법

1. 현재 환경에 설치·활성화된 스킬을 확인한다. 없다면 설치한 척하지 않고 가능한 일반 검토로 진행한다.
2. 소스 버전과 실행 화면을 맞춘 뒤 코드·설정·DB·로그·파일 저장소를 범위에 넣는다.
3. 보안은 코드 검토와 위협 모델링을 구분하고, 접근성은 자동 검사와 키보드·화면 읽기 도구 사용을 구분한다.
4. 각 발견 사항에 **실제 재현 / 자동 검사 / 코드 추정 / 미검증**을 표시한다.
5. 수정 후 같은 버전과 흐름에서 다시 확인한다. 법령 적용이나 인증 여부는 별도 담당자 판단으로 남긴다.

## 프롬프트 2. 보안·접근성 합동 인수 검토

```text
작업 모드: 읽기만. 개발 소스·운영 데이터·승인된 디자인을 수정하지 마.
대상 저장소와 커밋: [정확한 경로·해시]
검토 흐름: [로그인 → 본인확인 → 자격 확인 → 발급 → 조회]
기준 문서: [기능 정의·KWCAG·개인정보 처리방침·연동 규격]

현재 활성화된 스킬을 먼저 확인하고 사용할 스킬명·역할·지원 범위를 적어줘.
보안 코드 검토와 위협 모델링은 파일 근거와 미확인 가정을 분리해줘.
접근성은 실행 가능한 화면을 키보드로 조작하고, 자동 검사 결과와 수동 검수 결과를 분리해줘.
미설치 스킬을 사용했다고 쓰지 말고 실행하지 못한 검사는 미검증으로 표시해줘.
결과 표: 항목 | 근거 파일·화면 | 확인 방식 | 실제 결과 | 사용자 영향 | 수정·재검증 방법.
```
