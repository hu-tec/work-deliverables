# 밀도·그리드·좌측 정렬 UI 검토안

`index.html`은 밀도·그리드·좌측 정렬을 현행 디자인시스템 옆에서 검토하기 위한 **별도 시안**이다. 현행 `01_화면_디자인/디자인시스템/index.html`, `layout.css`, `accessibility_check.html`은 수정하지 않는다.

## 화면에서 볼 것

1. **밀도:** 같은 맥락의 짧은 정보를 한 줄에 묶고 반복 제목·빈 여백을 줄였는가. 글자나 조작 영역의 크기를 먼저 줄이지 않는다.
2. **그리드:** 제목·필터·표·상세의 시작선과 열 간격이 예측 가능한가. `정렬선 보기`로 축을 확인한다.
3. **좌측 정렬:** 제목·본문·라벨·값을 왼쪽부터 읽을 수 있는가. 상태와 주요 행동은 오른쪽의 일정한 위치를 쓴다.
4. **화면 목적:** 관리자 화면에서는 비교와 처리, 사용자 화면에서는 이해와 신청이 우선인가.
5. **간격 비교:** `제안: 촘촘하게`와 `비교: 넓게`를 오가며 한 화면에 들어오는 정보와 가독성을 비교한다.

## 스켈레톤 설명법

페이지의 6개 스켈레톤은 **헤더, 필터, 표+상세, 요약 카드, 폼, 랜딩**의 화면 구조를 보여준다. 각 스켈레톤에는 AI 작업 요청에 바로 쓸 수 있는 설명 문장을 붙였다. 실제 작업을 요청할 때는 `화면 목적 → 화면 구조/열 수 → 정렬 기준 → 데이터 출처 → 유지할 디자인 → 완료 검증` 순서로 덧붙인다.

## 눌러볼 수 있는 UI 패턴

산출물 페이지의 [`UI 패턴 예시` 탭](../../../index.html#ui-pattern-panel)에서는 실제 모양과 상태 변화를 확인할 수 있는 14가지 예시를 별도로 볼 수 있다. 같은 파일의 `index.html?view=patterns`가 탭 안에 표시된다.

| UI 패턴 | 확인할 동작 | 프롬프트에서 지정할 것 |
|---|---|---|
| 사이드바 | 현재 메뉴 강조, 하위 메뉴 접기·펼치기, 본문 제목 전환 | 메뉴 계층, 기본 펼침, 현재 위치, 좁은 화면 동작 |
| 경로·페이지 헤더 | 현재 위치·업무명·건수·상태·행동 표시 | 제목과 버튼 위치, 상태값 원천, 버튼 연결 기능 |
| 요약 카드·상태 | 선택한 수치 강조 | 요약 계산식, 클릭 시 결과 범위 |
| 인라인 Drawer | 목록 옆에 상세 열기·닫기 | 상세 필드, 닫기·초점 복귀, 좁은 화면 |
| 페이지 이동 | 행·페이지 표시·버튼 상태 변경 | 페이지 크기, 전체 건수, 정렬·필터 유지 |
| 알림 메시지 | 성공·오류 문구 표시·닫기 | 발생 조건, 지속 시간, 오류 후 행동 |
| 빈 결과·로딩 | 데이터 없음과 대기 상태 구분 | 빈 결과 문구, 재시도·초기화, 진행 표시 |
| 단계 표시 | 이전·다음 단계 전환 | 단계명, 이동 조건, 입력값 유지 |
| 탭 | 선택 탭 강조, 해당 본문만 전환 | 탭 이름, 기본 선택, 전환 시 유지할 데이터 |
| 접기·펼치기 | 제목을 누르면 상세 노출 | 최초 열림 상태, 한 번에 열 수 있는 개수 |
| 필터·상태 칩 | 선택 상태, 결과 행과 건수 변경 | 상태값 원천, 중복 선택 허용 여부, 빈 결과 |
| 표·상세 | 행 선택 시 우측 상세 갱신 | 핵심 열, 상세 필드, 좁은 화면 동작 |
| 입력 폼·피드백 | 필수값 확인, 완료 문장 표시 | 필수 필드, 검증 규칙, 실제 저장 경로 |
| 대화상자 | 열기·닫기 | 열리는 조건, 제목·본문, 취소·확인 행동 |

예시는 화면 구조와 동작을 설명할 뿐, 운영 자료를 조회·저장·전송하지 않는다. 실제 구현 요청에는 해당 기능 정의 문서와 데이터 원천을 별도로 연결해야 한다.

스켈레톤의 회색·파란색 막대는 실제 데이터가 아니다. 미리보기의 사람·과정·숫자도 구조 설명용 가상 정보이며, 실서비스에 옮기기 전에 정확한 원본 데이터와 연결해야 한다.
