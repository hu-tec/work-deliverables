표2·카드형2 대·중·소분류 작업 요청 가이드

생성일: 2026-07-02 최종 정리일: 2026-07-03 적용 범위: 자료 카탈로그형 표2·카드형2 전용

이 문서는 7열 자료 카탈로그에 적용하는 보조 가이드다. 검색조건·업무 테이블·회원 상세는 01_화면_디자인/디자인시스템/docs/재사용_디자인_프롬프트/공통/11_검색기능_테이블_상세보기_통합기준.md를 우선한다. 이 문서의 가로 스크롤 금지는 고정 7열 카탈로그에만 적용하며, 열이 많은 BO 업무 테이블 규칙을 덮어쓰지 않는다.

1. 이 문서의 목적

이 문서는 업무산출물이나 분석자료를 다음 두 방식으로 정리할 때 사용하는 작업 기준이다.

  • 표2: 대분류를 위에서 아래로 나열하고, 각 대분류 안에 전체 자료를 표로 보여주는 방식
  • 카드형2: 대분류 자체를 카드로 배치하고, 각 카드 안에 표2와 같은 표를 보여주는 방식

여기서 카드형은 자료 하나마다 독립된 카드가 생기는 방식이 아니다. 대분류 하나가 카드 하나이며, 카드 내부에는 자료 행으로 구성된 표가 들어간다.

이 문서를 기준으로 작업하면 다음 내용을 다시 길게 설명하지 않아도 된다.

  • 대분류·중분류·소분류의 의미
  • 표2와 카드형2의 차이
  • 날짜, 제목, 파일명, 다운로드 열 구성
  • 표2에서 오른쪽 미리보기를 여는 방식
  • 카드형2에서 팝업을 여는 방식
  • 개별·선택·대분류 다운로드 방식
  • 자료 개수와 다운로드 경로를 보존하는 방식

2. 다음에 사용할 가장 짧은 요청 문장

다음 문장으로 요청하면 이 문서 전체 기준을 적용한다.

표2·카드형2 대중소분류 작업 가이드 기준으로 [대상 파일]을 작업해줘. 먼저 실제 자료 개수와 대분류 구성을 확인하고, 자료와 다운로드 경로는 삭제하거나 바꾸지 마.

예시:

표2·카드형2 대중소분류 작업 가이드 기준으로 업무목록.html을 작업해줘. 표2 클릭은 오른쪽 미리보기, 카드형2 클릭은 팝업으로 열어줘.

분류안부터 확인하고 작업은 나중에 하려면 다음처럼 말한다.

표2·카드형2 대중소분류 작업 가이드 기준으로 이 파일을 분석해줘. 실제 자료 개수, 대분류명, 중분류명, 소분류 제목과 개수를 표로 설명만 하고 아직 수정하지 마.

3. 작업 요청에 반드시 포함하면 좋은 정보

3.1 대상 파일

수정할 HTML 파일의 전체 경로나 파일명을 지정한다.

예시:

C:\Users\itban\Desktop\까마귀\신봄_업무산출물(0605)\analyze.html

3.2 분류 유지 또는 변경 여부

다음 중 하나를 분명히 말한다.

  • 기존 대분류를 그대로 유지한다.
  • 특정 대분류만 합친다.
  • 큰 대분류를 여러 개로 나눈다.
  • 분류안을 먼저 설명하고 승인 후 작업한다.

예시:

기존 분류는 그대로 두고 정보구조/사이트맵 분석만 3개 대분류로 나눠줘.

3.3 클릭 결과

별도로 말하지 않으면 다음 규칙을 적용한다.

  • 표2: 오른쪽 미리보기 영역에서 연다.
  • 카드형2: 화면 중앙 팝업에서 연다.
  • 카드형2 항목을 클릭해도 표2로 강제 전환하지 않는다.
  • 카드형2 항목을 클릭해도 페이지 아래쪽 미리보기를 갱신하지 않는다.

3.4 원본 보호 여부

별도로 말하지 않으면 다음 항목을 보존한다.

  • 원본 HTML과 Markdown 파일
  • 파일 경로와 폴더 구조
  • 기존 ZIP 파일
  • 다운로드 경로
  • 만든날과 수정날 데이터
  • 기존 미리보기 연결 관계

4. 대분류·중분류·소분류의 정확한 의미

4.1 대분류

대분류는 화면에서 가장 큰 자료 묶음이다.

표2에서는 대분류가 위에서 아래로 이어지는 독립 섹션이다. 카드형2에서는 대분류 하나가 카드 하나가 된다.

대분류 제목 옆에는 해당 대분류에 포함된 실제 소분류 행 개수를 표시한다.

예시:

사이트 분석 7개
FAQ 분석 4개
내부 플랫폼 분석 3개

대분류 개수는 보기 좋게 임의로 정하지 않는다. 실제 업무 맥락과 자료 개수를 함께 본 뒤 정한다.

  • 한 대분류에 자료가 지나치게 많으면 의미에 따라 나눈다.
  • 같은 업무 맥락의 작은 분류는 합칠 수 있다.
  • 합치거나 나누기 전에는 기존 자료 제목과 개수를 먼저 확인한다.
  • 자료를 분류에서 제외해 개수를 줄이지 않는다.

4.2 중분류

중분류는 대분류 안에서 자료를 한 단계 더 나눌 필요가 있을 때만 사용한다.

예를 들어 분석·홈페이지 기획이라는 대분류를 유지한다면 다음 두 중분류를 둘 수 있다.

대분류: 분석·홈페이지 기획
├─ 중분류: 분석자료 확인 방법 8개
└─ 중분류: 홈페이지 구성 방향 4개

하지만 두 항목을 각각 독립된 대분류로 분리하기로 결정했다면 중분류 제목을 다시 반복하지 않는다.

대분류: 분석자료 확인 방법 8개
대분류: 홈페이지 구성 방향 4개

즉, 중분류는 항상 표시하는 장식용 제목이 아니다. 대분류 안에 서로 다른 맥락의 자료 묶음이 실제로 함께 들어 있을 때만 사용한다.

4.3 소분류

소분류는 표의 실제 한 행에 해당하는 개별 자료다.

소분류 하나는 다음 정보를 가진다.

제목
파일 경로
파일 형식
만든날
수정날
다운로드 경로
설명
관련 Markdown 경로

소분류 개수는 화면에 표시된 실제 행 개수와 일치해야 한다.

예를 들어 대분류 제목에 9개라고 표시되면 표 본문에도 반드시 9개 행이 있어야 한다.

  • 일부 행을 접어서 숨기지 않는다.
  • 첫 5개만 보여주고 나머지를 생략하지 않는다.
  • 카드 높이가 부족하다는 이유로 행을 자르지 않는다.
  • 검색 중에는 검색 결과에 맞춰 개수를 다시 계산한다.

6. 표2 화면 규칙

6.1 기본 구조

표2는 다음 구조로 만든다.

상단 검색·보기 전환·선택 다운로드
└─ 왼쪽 자료 목록
   ├─ 대분류 제목과 개수
   └─ 전체 자료 표

가운데 또는 오른쪽 미리보기
└─ 선택한 HTML 또는 Markdown 내용

관련 Markdown 영역이 있는 경우
└─ 선택 자료와 연결된 Markdown 원문

6.2 표 열 순서

표 열은 반드시 다음 순서를 사용한다.

선택순서수정날제목파일명만든날다운

각 열의 의미는 다음과 같다.

열내용
선택여러 자료를 한꺼번에 다운로드하기 위한 체크박스
순서해당 대분류 안에서의 표시 순서
수정날파일 또는 자료가 마지막으로 수정된 날짜
제목사람이 이해하기 쉬운 자료 제목
파일명실제 경로의 마지막 파일명 또는 폴더명
만든날파일 또는 자료가 처음 만들어진 날짜
다운해당 행 자료를 내려받는 버튼

6.3 촘촘한 표 배치

가로 스크롤바 없이 일곱 개 열이 보여야 한다.

  • 표 너비는 컨테이너의 100%를 사용한다.
  • 강제 최소 너비를 사용하지 않는다.
  • table-layout: fixed 방식으로 열 너비를 안정적으로 유지한다.
  • 선택, 순서, 날짜, 다운로드 열은 고정된 좁은 폭을 사용한다.
  • 제목과 파일명 열이 남은 너비를 나눠 사용한다.
  • 열 사이의 세로 구분선은 표시하지 않는다.
  • 각 행 아래의 가로 구분선만 사용한다.
  • 셀 안쪽 여백은 작게 유지한다.

권장 폭의 개념은 다음과 같다.

선택      약 22px
순서      약 24px
수정날    약 50px
제목      남은 공간의 약 28%
파일명    남은 공간의 약 22%
만든날    약 50px
다운      약 26px

6.4 제목과 파일명 표시

제목은 최대 두 줄까지 표시할 수 있다. 긴 제목 때문에 표 전체 폭이 늘어나면 안 된다.

파일명은 다음 규칙을 적용한다.

  • 경로 전체가 아니라 마지막 파일명 또는 폴더명을 사용한다.
  • 긴 파일명은 뒤쪽 내용을 우선한다.
  • _, -, 공백으로 구분한 단어 중 뒤쪽 최대 5단어를 표시한다.
  • 단어 구분이 없는 긴 파일명은 뒤쪽 글자를 표시한다.
  • 화면 표시만 줄이고 실제 링크와 다운로드 경로는 바꾸지 않는다.
  • 마우스를 올리면 전체 경로를 툴팁으로 확인할 수 있게 한다.

예시:

원본: 01_화면_디자인/디자인시스템/table_design/관리자패널_전체회원_상세_화면.html
표시: …table_design_관리자패널_전체회원_상세_화면.html
실제 링크: 원본 경로 그대로 유지

6.5 표2 클릭 동작

표2에서는 다음 영역을 클릭할 수 있다.

  • 제목 버튼
  • 파일명 버튼
  • 체크박스와 다운로드 버튼을 제외한 행의 빈 영역

클릭 결과는 팝업이 아니라 오른쪽 미리보기다.

  • HTML: iframe으로 오른쪽 미리보기 영역에 표시
  • Markdown: 렌더링한 본문을 오른쪽에 표시
  • 폴더 또는 ZIP: 설명과 자료 열기 링크 표시
  • 관련 Markdown이 있으면 별도의 관련 Markdown 영역에 함께 표시

표2 상단 미리보기에는 다음 버튼이 있어야 한다.

버튼동작
오른쪽만 보기왼쪽 목록을 숨기고 미리보기 영역을 넓힌다. 다시 누르면 목록을 표시한다.
Markdown 닫기관련 Markdown 영역을 닫는다. 다시 누르면 Markdown 열기로 바뀐다.
전체 화면으로 보기선택한 실제 HTML 또는 Markdown 경로를 새 창에서 연다.

버튼은 실제 상태와 문구가 일치해야 한다.

오른쪽만 보기 ↔ 목록 함께 보기
Markdown 닫기 ↔ Markdown 열기
본문 닫기 ↔ 본문 열기

7. 카드형2 화면 규칙

7.1 카드의 단위

카드형2의 카드 단위는 개별 자료가 아니라 대분류다.

잘못된 방식:

자료 1 = 카드 1개
자료 2 = 카드 1개
자료 3 = 카드 1개

올바른 방식:

대분류: 사이트 분석 = 카드 1개
└─ 카드 안에 자료 7개 표

대분류: FAQ 분석 = 카드 1개
└─ 카드 안에 자료 4개 표

7.2 카드 안의 표

카드 내부의 표도 표2와 같은 열을 사용한다.

선택 · 순서 · 수정날 · 제목 · 파일명 · 만든날 · 다운

표2와 카드형2에서 다음 정보가 달라지면 안 된다.

  • 자료 개수
  • 행 순서
  • 날짜
  • 제목
  • 파일명
  • 다운로드 경로
  • 체크박스 상태

가능하면 표2와 카드형2가 같은 표 생성 함수를 사용하게 만들어 두 보기의 차이를 줄인다.

7.3 카드 높이

카드 높이는 포함된 소분류 수에 따라 자동으로 늘어난다.

  • 3개 자료 카드는 3개 행을 표시한다.
  • 9개 자료 카드는 9개 행을 모두 표시한다.
  • 20개 자료 카드는 20개 행을 모두 표시한다.
  • 고정 높이로 행을 자르지 않는다.
  • 카드 내부 세로 스크롤로 일부 행을 감추지 않는다.
  • 페이지 자체의 세로 스크롤은 사용할 수 있다.

7.4 카드 배치

기준 업무 화면에서는 다음처럼 배치한다.

화면카드 열 수
기준 업무 화면4단

이 가이드는 기준 업무 화면의 4단 배치만 정의한다. 별도 요청이 없으면 반응형 규칙을 추가하지 않는다.

7.5 카드형2 클릭 동작

카드형2에서는 항목을 클릭하면 중앙 팝업을 연다.

다음 동작은 금지한다.

  • 카드 항목 클릭 후 표2로 자동 전환
  • 카드 항목 클릭 후 페이지 아래 미리보기 갱신
  • 카드 항목 클릭 후 새 페이지로 바로 이동
  • 카드 높이 안에서 원문 전체를 펼쳐 다른 카드를 밀어냄

팝업은 다음 구조를 사용한다.

어두운 배경 오버레이
└─ 중앙 팝업
   ├─ 제목
   ├─ 만든날·수정날·경로
   ├─ 전체 화면으로 보기
   ├─ 닫기
   └─ HTML iframe 또는 렌더링한 Markdown 본문

팝업은 다음 방법으로 닫을 수 있어야 한다.

  • 닫기 버튼
  • 팝업 바깥의 어두운 배경 클릭
  • 키보드 Esc

팝업이 열려 있을 때는 배경 페이지가 스크롤되지 않게 한다.

---

8. 검색과 보기 전환

검색은 다음 내용을 함께 검색한다.

  • 대분류 제목
  • 중분류 제목
  • 소분류 제목
  • 파일명과 전체 경로
  • 자료 설명

검색 결과에서는 대분류 옆 개수도 검색된 실제 행 개수로 바뀌어야 한다.

보기 전환 규칙:

  • 기본값은 별도 요청이 없으면 표2로 한다.
  • 표2와 카드형2 버튼 중 현재 보기를 명확하게 표시한다.
  • 카드형2로 전환할 때 오른쪽만 보기 상태가 남아 목록이 사라지지 않게 한다.
  • 보기 전환 시 열려 있던 팝업은 닫는다.
  • 표2로 돌아오면 오른쪽 미리보기 영역을 다시 사용할 수 있어야 한다.

---

9. 날짜 규칙

수정날과 만든날은 서로 다른 열로 유지한다.

  • 화면 표시는 예외 없이 YY-MM-DD를 사용한다.
  • 내부 데이터가 2026-06-04여도 화면에는 26-06-04로 표시한다.
  • 만든날과 수정날이 같아도 두 열을 모두 표시한다.
  • 날짜를 확인할 수 없으면 추측하지 않고 -로 표시한다.
  • 상시 접속 URL처럼 날짜가 의미 없는 경우 상시 등의 명확한 값을 사용할 수 있다.

날짜 데이터를 새로 만들거나 임의로 바꾸지 않는다.

10. 다운로드 규칙

10.1 개별 다운로드

각 행의 다운 열에 다운로드 버튼을 둔다.

  • 파일은 해당 파일을 직접 다운로드한다.
  • 폴더 자료는 기존에 연결된 ZIP이 있으면 ZIP을 다운로드한다.
  • 외부 URL이나 다운로드할 수 없는 항목은 버튼을 비활성화한다.

10.2 선택 다운로드

각 행 앞에 체크박스를 둔다.

사용자가 여러 행을 선택한 뒤 선택 다운로드를 누르면 선택한 여러 파일을 순서대로 다운로드한다.

  • 선택 개수를 표시한다.
  • 선택 해제 버튼을 제공한다.
  • 선택한 자료가 없으면 버튼을 비활성화한다.
  • 브라우저의 여러 파일 다운로드 허용이 필요할 수 있다.

10.3 대분류 전체 다운로드

대분류 제목 옆에 대분류 전체 다운로드 버튼을 둘 수 있다.

  • 기존 대분류 ZIP이 있으면 그 ZIP을 사용한다.
  • 여러 기존 분류를 하나로 합친 경우 연결된 ZIP을 모두 순서대로 다운로드할 수 있다.
  • 새 ZIP을 만들지 않았다면 존재하지 않는 경로를 임의로 연결하지 않는다.

10.4 HTML과 Markdown 원본

하나의 산출물이 HTML과 Markdown 원본을 함께 가져야 하는 경우 두 파일을 모두 다운로드 대상으로 연결한다.

화면 표시용 파일명 축약은 다운로드 대상에 영향을 주면 안 된다.

---

11. 원문 미리보기 규칙

11.1 HTML

HTML은 iframe으로 표시한다.

  • 표2: 오른쪽 미리보기
  • 카드형2: 중앙 팝업
  • 전체 화면으로 보기: 실제 HTML 경로를 새 창으로 연다.

11.2 Markdown

Markdown은 내장된 원문을 HTML로 렌더링해 표시한다.

지원할 기본 요소:

  • 제목 1~3단계
  • 문단
  • 순서 목록과 일반 목록
  • 코드 블록
  • 인라인 코드
  • 링크
  • 인용문
  • Markdown 표

11.3 관련 Markdown

HTML 자료와 기준 Markdown이 연결되어 있으면 표2의 오른쪽 관련 Markdown 영역에 표시한다.

  • 여러 Markdown이 연결되면 탭 또는 버튼으로 전환한다.
  • 원문 열기 링크를 제공한다.
  • Markdown 닫기/열기 버튼이 실제로 작동해야 한다.

카드형2 팝업에서는 우선 선택한 자료 자체를 보여준다. 관련 Markdown을 팝업에 추가할지는 별도 요청으로 결정한다.

12. 데이터 구조 권장 형태

자료를 코드에서 다음과 같은 구조로 다루면 표2와 카드형2를 일관되게 만들 수 있다.

        title: '',
        items: [
          {

15. 작업 요청 예시

15.1 분류만 먼저 확인

표2·카드형2 대중소분류 작업 가이드 기준으로 report.html을 분석해줘.

중복되거나 같은 맥락인 자료는 합칠 수 있는지 의견을 줘.
아직 파일은 수정하지 마.

15.2 기존 분류를 그대로 적용

표2·카드형2 대중소분류 작업 가이드 기준으로 report.html을 작업해줘.

원본 파일, 날짜, 다운로드 경로는 변경하지 마.

15.3 특정 대분류만 나누기

표2·카드형2 대중소분류 작업 가이드 기준으로 analyze.html을 작업해줘.

  • [ ] 모든 행이 생략 없이 보인다.
  • [ ] 카드 높이가 자료 수에 맞게 자동 확장된다.
  • [ ] 카드 클릭 시 표2로 전환되지 않는다.
  • [ ] 카드 클릭 시 중앙 팝업이 열린다.
  • [ ] 닫기, 배경 클릭, Esc로 팝업을 닫을 수 있다.
  • [ ] 기준 업무 화면에서 4단으로 표시된다.

다운로드 검수

  • [ ] 개별 다운로드가 실제 파일을 가리킨다.
  • [ ] 체크박스 선택 다운로드가 작동한다.
  • [ ] 선택 해제가 작동한다.
  • [ ] 대분류 전체 다운로드가 기존 ZIP 또는 파일 묶음을 가리킨다.
  • [ ] 화면에 축약된 파일명 때문에 실제 경로가 변경되지 않았다.

안전 검수

  • [ ] 접근성 점검 페이지 크기를 변경하지 않았다.
  • [ ] 요청 없이 GitHub에 올리지 않았다.
  • [ ] HTML 태그 구조와 JavaScript 문법을 검사했다.
  • [ ] 기존 자료와 다운로드 파일을 삭제하지 않았다.

19. 최종 요청 문장 권장본

새 파일에 지금과 같은 구조를 그대로 적용하려면 다음 문장을 사용한다.

표2·카드형2 대중소분류 작업 가이드 기준으로 [파일명]을 작업해줘.

먼저 실제 자료 전체 개수와 현재 분류를 확인하고,
대분류·중분류·소분류 구조와 각 개수를 표로 정리해.
내가 분류 변경을 따로 말하지 않으면 기존 대분류를 유지해.

표2와 카드형2 모두
선택 · 순서 · 수정날 · 제목 · 파일명 · 만든날 · 다운
순서의 촘촘한 표를 사용하고 가로 스크롤은 없애.

표2에서는 제목, 파일명 또는 행을 클릭하면 오른쪽 미리보기에서 열고,
오른쪽만 보기, Markdown/본문 닫기, 전체 화면으로 보기 버튼을 작동시켜.

카드형2에서는 대분류 하나를 카드 하나로 만들고 카드 안에 같은 표를 넣어.
카드 높이는 전체 행이 보이도록 자동으로 늘리고,
항목 클릭 시 표2로 전환하거나 아래에 표시하지 말고 중앙 팝업으로 열어.

파일명은 뒤쪽 최대 5단어만 표시하되 전체 경로와 다운로드 경로는 유지해.
원본 HTML, Markdown, ZIP, 만든날, 수정날과 다운로드 기능은 삭제하거나 바꾸지 마.
접근성 점검 페이지의 실제 권장 크기는 절대 변경하지 마.
GitHub에는 올리지 마.

이 요청문과 이 가이드를 함께 기준으로 사용하면 현재 인수인계서와 analyze.html에 적용한 표2·카드형2 구조를 다른 자료 화면에도 동일하게 재현할 수 있다.
