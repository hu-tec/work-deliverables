01. 말로만 설명하지 않는 세 가지 기준

화면에서 관찰할 수 있는 판단 기준
밀도 = 중복을 덜고 비교를 빠르게

검색조건·상태·첫 행을 한 화면에서 이어 읽습니다. 글자를 먼저 줄이지 않고 반복 제목, 큰 카드 여백, 불필요한 줄바꿈을 정리합니다.

확인: 첫 화면에서 업무명 → 조건 → 결과 → 다음 행동이 보이는가?
그리드 = 같은 성격은 같은 축에

필터는 4열, 목록은 열 정렬, 상세는 이름과 값의 2열 기준을 씁니다. 긴 설명과 큰 표는 무리하게 여러 열로 나누지 않습니다.

확인: 제목·필터·표·상세가 공통 시작선과 열 규칙을 따르는가?
좌측 정렬 = 읽기 시작점의 일관성

제목·본문·라벨·값·표의 문자를 왼쪽에서 읽기 시작합니다. 오른쪽은 상태·주요 버튼처럼 위치가 일정해야 할 행동에만 씁니다.

확인: 시선이 화면 안에서 불필요하게 좌우로 왕복하지 않는가?

03. 화면 구조를 스켈레톤으로 설명하기

실제 자료를 연결하기 전 배치 순서 지정
① 헤더·상태·행동업무 첫 줄

화면명은 왼쪽, 현재 상태와 주요 행동은 오른쪽의 고정 위치에 둡니다.

“제목·건수·상태·주요 버튼을 첫 줄에 배치하고, 제목과 본문 시작선을 맞춰줘.”
② 검색·필터짧은 조건 4열

같은 맥락의 짧은 조건을 같은 줄에 묶고, 선택 상태를 바로 읽게 합니다.

“필터는 데스크톱 4열로 묶고, 라벨·선택값의 시작선을 통일해줘.”
③ 표·상세 패널비교와 처리

표에서 여러 건을 비교하고 선택한 한 건의 정보를 옆에서 처리합니다.

“왼쪽은 목록 표, 오른쪽은 선택 행 상세로 두고 핵심 열은 유지해줘.”
④ 요약 카드짧은 값 비교

독립된 요약 정보에만 카드를 쓰고 카드 안에 카드를 반복하지 않습니다.

“요약값 3개를 같은 너비의 카드로 보여주되 과한 높이와 중첩 테두리를 피해줘.”
⑤ 입력·신청 폼읽는 순서 유지

짧은 값은 2열, 긴 설명이나 메모는 1열로 쓰고 저장 행동을 찾기 쉽게 둡니다.

“짧은 입력은 2열, 긴 설명은 전체 폭으로 두고 필드 라벨을 좌측 정렬해줘.”
⑥ 랜딩·안내 화면이해와 신청

핵심 문구와 행동을 왼쪽에 두고, 대상·일정·방식은 짧은 정보 그리드로 이어갑니다.

“제목·설명·신청 버튼을 좌측 정렬하고 핵심 안내는 4열 정보 그리드로 보여줘.”

04. 검토할 때 확인할 것

시안 확정 전 판단 항목
  • 첫 화면에서 화면 목적과 다음 행동이 바로 보이는가?
  • 같은 성격의 정보가 같은 열과 시작선을 쓰는가?
  • 빈 공간을 줄여도 본문과 조작 요소가 읽기 쉬운가?
  • 표의 핵심 열은 좁은 화면에서도 접근 가능한가?
  • 사용자 화면은 관리자 화면보다 여유 있게 읽히는가?
  • 현행 디자인시스템의 색상·상태 표현과 연결되는가?

이 페이지는 UI 구조와 동작을 검토하기 위한 별도 시안입니다. 현행 디자인시스템의 접근성 기준 화면과 크기 규칙은 수정하지 않았습니다. 위 상호작용은 예시 데이터만 바꾸며 실제 업무 데이터를 저장하거나 전송하지 않습니다.
