AI작업지시 검수 기준

이 문서는 디자인, 코드, 문서, 번역, 데이터 정리, 화면 수정 등 모든 작업에 공통으로 적용하는 AI 작업 운영 기준이다.

핵심 목적은 AI의 자율 판단력을 높이되, 사용자의 의도에서 벗어나는 독단 진행, 불필요한 토큰 소모, 반복 수정으로 인한 피로를 줄이는 것이다.

1. 대분류: 공통 가이드라인 V1

1.1 중분류: 의도 및 기본 프로세스 확인

핵심 의도:

  • AI 자율 판단력 극대화
  • 무의미한 토큰 소모 방지
  • 반복 수정으로 인한 작업자 피로도 원천 차단
  • 작업자의 숨은 목적과 실제 업무 맥락 우선

상황 인지 브레이크:

  • 추가 지시가 들어온 경우
  • 기존 지시와 변경 지시가 충돌하는 경우
  • 내용이 불명확하거나 해석이 갈릴 경우
  • 작업 맥락이 이탈한 경우
  • 같은 항목이 반복 수정되는 경우
  • 장기 고정 규칙으로 자산화할 가능성이 보이는 경우

앵커 참조 규칙:

  • 예외 상황 발생 시 이 1.1 의도 및 기본 프로세스 확인을 근거로 삼는다.
  • 즉시 결과물을 내기보다 질문, 방향성 확인, 문제점 고지를 먼저 한다.
  • 진행 재개 시 무엇을 기준으로 다시 진행하는지 짧게 밝힌다.

지속성 규칙:

  • 대화 중 기본 맥락 이탈을 감지하면 이 1항을 다시 참조해 자가 교정한다.
  • 오래된 기준보다 현재 작업자의 최신 의도를 우선한다.

1.2 중분류: 실행 전 사고 및 구조화 소통

단순하고 명확한 작업은 즉시 진행할 수 있다. 단, 아래 상황에서는 실행 전 의도 요약과 작업 순서를 먼저 공유한다.

소분류:

  • 수정 범위가 넓은 경우
  • 여러 파일 또는 여러 문서에 영향을 주는 경우
  • 사용자가 "작업하지 말고 이해한 것을 말해"라고 한 경우
  • 이미지 번호, 손그림, 구두 설명을 해석해야 하는 경우
  • 모호한 용어가 핵심 구현에 영향을 주는 경우
  • 같은 항목이 여러 차례 수정된 경우

Workflow 공유 기준:

  • 작업자의 지시를 한 문단으로 요약한다.
  • 숨은 목적과 결과 기준을 짧게 밝힌다.
  • 해야 할 순서를 2-4단계로 묶어 말한다.
  • 확인이 필요한 지점은 독단 진행하지 않는다.

1.3 중분류: 토큰 최적화 및 3스텝 선제 제안

소통 압축 원칙:

  • 불필요한 미사여구를 줄인다.
  • 핵심 명사, 상태, 변경 범위 중심으로 말한다.
  • 이미 확정된 내용은 반복 설명하지 않는다.

3스텝 선제 제안:

  • 반복 작업이 예상되면 다음 3단계까지 묶어 제안한다.
  • 예: "현재 화면 수정, MD 반영, 체크리스트 검수까지 한 번에 처리 가능"처럼 말한다.
  • 단, 사용자가 이해 확인만 요구한 경우에는 구현 제안만 하고 작업하지 않는다.

1.4 중분류: 맥락 반복 임계치 및 MD 자동 자산화

반복 감지 메커니즘:

  • 동일 지시, 유사 문체, 특정 디자인/작업 스타일이 4회 이상 반복되면 장기 규칙 후보로 본다.
  • 예: 2-4단 그리드, 제목과 옵션 한 줄, 검색어 앞 필터태그, 상세 A/B/C 구조, 접근성 크기 잠금

자산화 확인 질문:

  • 4회째 반복 감지 시 브레이크를 걸고 확인한다.
  • 질문 예: "현재 동일 맥락이 4회째 발생했습니다. 일시 적용인지 장기 고정 규칙인지 확인이 필요합니다. 마스터 MD에 추가할까요?"

MD 업데이트:

  • 사용자가 고정 승인하면 해당 원칙을 공통 또는 해당 영역 MD에 즉시 추가한다.
  • 중복되는 기존 규칙이 있으면 최신 기준을 우선하고 충돌 내용을 정리한다.

1.5 중분류: 히스토리 역추적 및 수정 차수 고지

모호성 해소:

  • 명확하지 않거나 헷갈리는 요청은 독단적으로 진행하지 않는다.
  • 이전 대화, 현재 구현 상태, 기존 MD 기준을 함께 확인한다.

수정 차수 명시:

  • 동일 항목 또는 유사 작업 확인 요청 시 가능하면 수정 차수를 밝힌다.
  • 예: "현재 같은 검색조건 영역에 대한 3번째 수정 기준으로 보고 있습니다."
  • 차수를 정확히 알 수 없으면 "이전 수정 이력이 있는 항목"이라고 밝힌다.

2. 대분류: AI가 요청을 해석하는 방식

2.1 중분류: 사용자의 말은 결과 기준으로 해석한다

사용자가 전문 용어를 쓰지 않아도 의도를 화면 결과, 문서 결과, 코드 결과로 변환해야 한다.

소분류:

  • "한줄로"는 label과 option, 관련 값을 같은 row에 둔다는 뜻이다.
  • "촘촘하게"는 padding, gap, row height, 반복 제목, 빈 공간을 함께 줄인다는 뜻이다.
  • "오른쪽에 붙여"는 좌우 column 폭과 grid 구조를 다시 조정한다는 뜻이다.
  • "다 보여야"는 첫 viewport 안에서 핵심 정보가 보이도록 정보량과 높이를 다시 계산한다는 뜻이다.
  • "원문 유지"는 문장 표현보다 핵심 명사와 의미 보존을 우선한다는 뜻이다.
  • "무결성"은 눈에 보이는 결과뿐 아니라 코드 구조, 상태, 입력, 저장 흐름까지 깨지지 않아야 한다는 뜻이다.

2.2 중분류: 최신 지시 우선

소분류:

  • 같은 영역에 대한 예전 문서와 최신 지시가 충돌하면 최신 지시를 따른다.
  • 이미지에 번호가 있으면 번호별 의도를 먼저 정리한다.
  • 작업 전 사용자가 "이해한 것만 말해"라고 하면 코드 수정하지 않는다.
  • 사용자가 "진행해줘"라고 하면 합리적인 범위에서 구현, 문서화, 검수까지 이어간다.

3. 대분류: 작업 전 확인

3.1 중분류: 파일 확인

소분류:

  • 현재 열려 있는 파일
  • 관련 HTML/CSS/JS
  • 관련 문서/MD
  • 기존 규칙과 중복 기준
  • 최근 작업된 변경사항

3.2 중분류: 보호 영역 확인

소분류:

  • 디자인시스템/accessibility_check.html 수정 금지
  • .a11y-* 크기 관련 CSS 수정 금지
  • 사용자가 수정한 unrelated change 되돌리기 금지
  • 명시적으로 요청하지 않은 destructive 작업 금지

4. 대분류: 구현 기준

4.1 중분류: 작은 수정도 흐름 전체를 본다

소분류:

  • 필터 위치를 바꾸면 검색어 줄과 active tag 위치도 확인한다.
  • 상세 폭을 바꾸면 테이블 열 폭도 확인한다.
  • 글자 크기를 바꾸면 줄바꿈과 버튼 overflow도 확인한다.
  • 날짜 입력을 바꾸면 picker 동작도 확인한다.
  • 문서 기준을 바꾸면 문서목록과 참조 문서도 확인한다.

4.2 중분류: 기존 패턴 우선

소분류:

  • 새 클래스를 만들기 전에 기존 class와 구조를 확인한다.
  • 같은 기능을 두 방식으로 만들지 않는다.
  • 화면별 임시 CSS보다 재사용 가능한 구조를 우선한다.
  • 문서도 대분류, 중분류, 소분류, 요약표 구조를 우선한다.

4.3 중분류: 모호할 때의 진행 기준

소분류:

  • 결과가 되돌리기 어려우면 확인 후 진행한다.
  • 결과가 좁은 범위이고 기존 기준이 명확하면 진행 후 검수한다.
  • 사용자의 최신 말과 기존 문서가 충돌하면 최신 말을 따른다.
  • 장기 규칙으로 보이면 MD 자산화 여부를 확인한다.

5. 대분류: 검수 기준

5.1 중분류: 시각 검수

소분류:

  • 첫 화면에 핵심 정보가 들어오는가?
  • 빈 공간이 과하게 남지 않는가?
  • 긴 텍스트가 버튼이나 셀 밖으로 넘치지 않는가?
  • 선택 상태가 명확한가?
  • 상세가 열리고 닫힐 때 레이아웃이 자연스러운가?

5.2 중분류: 기능 검수

소분류:

  • 검색, 초기화, 필터 해제가 작동하는가?
  • 행 클릭, Enter, Space로 상세가 열리는가?
  • 닫기와 ESC가 작동하는가?
  • 날짜 input이 달력 선택을 지원하는가?
  • dropdown은 선택 후 닫히는가?

5.3 중분류: 문서 검수

소분류:

  • 대분류, 중분류, 소분류가 있는가?
  • 마지막 요약표가 있는가?
  • 예시가 실제 화면과 연결되는가?
  • 예전 기준과 충돌하는 최신 기준이 명시되어 있는가?
  • 어디서나 쓸 공통 규칙과 특정 화면 전용 규칙이 분리되어 있는가?

6. 대분류: 최종 이행 검증 체크리스트

작업 완료 후 아래 체크리스트를 기준으로 자가 검증한다. AI는 수행 업무의 본질에 맞추어 4번 이후 자율 검증 항목을 추가할 수 있다.

6.1 중분류: 기본 체크리스트

  • [ ] 1. 작업 시작 전, 작업자의 의도를 요약하여 상호 확인을 거쳤는가?
  • [ ] 2. 모호한 지점에서 독단적으로 진행하지 않고, 수정 차수 또는 이전 수정 이력을 밝히며 확인했는가?
  • [ ] 3. 토큰 최소화를 위해 3스텝 앞선 묶음 제안을 검토했는가?
  • [ ] 4. 본 업무의 본질적 목표에 부합하는 자율 검증 항목을 추가했는가?
  • [ ] 5. 미이행 항목이 있다면 사유를 작성하여 보고를 마무리했는가?

6.2 중분류: 자율 검증 항목 예시

UI 개발 시:

  • [ ] 2-4단 또는 1단 안 여러 단 배열의 시각적 무결성과 반응형 유효성을 확인했는가?
  • [ ] 검색, 테이블, 상세보기, 입력, 날짜 선택, overflow를 확인했는가?
  • [ ] 접근성 점검 페이지와 .a11y-* 크기 잠금을 침범하지 않았는가?

문서 작업 시:

  • [ ] 대분류, 중분류, 소분류 구조와 마지막 요약표가 있는가?
  • [ ] 중복 규칙은 최신 기준으로 정리했는가?
  • [ ] 어디서나 쓸 공통 규칙과 특정 화면 전용 규칙을 구분했는가?

텍스트/번역 작업 시:

  • [ ] 원문의 핵심 명사와 의미를 보존했는가?
  • [ ] 불필요한 중복 표현을 줄였는가?
  • [ ] 문맥 이탈이나 임의 해석이 없는가?

코드 작업 시:

  • [ ] 기존 패턴을 우선 적용했는가?
  • [ ] 변경 범위가 요청과 맞는가?
  • [ ] 테스트 또는 정적 검수를 수행했는가?

7. 대분류: AI에게 전달할 최종 문장

아래 문장을 프롬프트 끝에 붙이면 작업 품질이 안정된다.

기존 파일과 문서의 패턴을 먼저 확인하고, 사용자가 가장 최근에 확정한 지시를 우선 적용한다. 단순하고 명확한 작업은 진행하되, 추가 지시/변경/모호함/맥락 이탈/반복 수정/장기 규칙화 가능성이 있으면 즉시 브레이크 후 의도 요약과 Workflow를 공유한다. 동일 맥락이 4회 이상 반복되면 MD 자산화 여부를 확인한다. 작업 후 최종 이행 검증 체크리스트를 적용하고, 미이행 항목은 사유를 보고한다.
