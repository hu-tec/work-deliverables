화면목적 정보우선순위 기준

1. 대분류: 화면 목적 먼저 잡기

1.1 중분류: 화면의 진짜 목적

화면을 만들 때 첫 질문은 "무엇을 예쁘게 보일까"가 아니라 "사용자가 이 화면에서 어떤 결정을 하거나 어떤 일을 끝내야 하는가"다.

소분류:

  • 사용자 안내 화면: 이해, 신청, 확인, 이동이 목적이다.
  • 관리자 화면: 검색, 비교, 판단, 수정, 저장, 이력 확인이 목적이다.
  • DB/테이블 화면: 많은 행을 빠르게 찾고 상태를 비교하는 것이 목적이다.
  • 상세 작업 화면: 선택한 한 건을 처리하고 메모와 이력을 남기는 것이 목적이다.

1.2 중분류: 자연어 요청 해석

사용자가 "촘촘하게", "한눈에", "빈 공간 없이", "관리자가 편하게"라고 말하면 문장 그대로 CSS 한두 개만 바꾸지 않는다.

소분류:

  • "촘촘하게": 여백, 행 높이, 중복 제목, 줄바꿈, 빈 영역을 함께 줄인다.
  • "한눈에": 중요한 상태와 다음 행동을 첫 viewport 안에 보이게 한다.
  • "편하게": 너무 빽빽해서 읽기 어려운 상태가 아니라, 반복 업무에 필요한 값이 정리되어 보이는 상태다.
  • "빈 공간 없이": 정보를 억지로 채우는 뜻이 아니라 같은 맥락의 정보를 같은 줄 또는 같은 영역에 묶는 뜻이다.

2. 대분류: 정보 우선순위

2.1 중분류: 항상 먼저 보여야 하는 정보

소분류:

  • 현재 화면명 또는 업무명
  • 선택된 대상의 대표명과 식별번호
  • 현재 상태
  • 검색조건 또는 필터 상태
  • 테이블의 첫 행 또는 상세 작업 시작점
  • 저장, 닫기, 넓게보기 같은 핵심 행동

2.2 중분류: 접거나 뒤로 보낼 수 있는 정보

소분류:

  • 긴 설명문
  • 과거 이력 전체
  • 보조 메모
  • 운영자만 가끔 확인하는 참고값
  • 화면 전체 의미를 반복 설명하는 문구

2.3 중분류: 위치가 바뀌면 안 되는 정보

관리 화면에서 위치가 계속 바뀌면 하루 종일 보는 직원이 피로해진다.

소분류:

  • 상태 chip은 같은 위치에 둔다.
  • 저장/닫기/넓게보기는 같은 영역에 둔다.
  • 선택된 행의 기본정보는 상세 패널 왼쪽 또는 상단 고정 영역에 둔다.
  • 업무 입력 영역은 고정정보와 섞지 않는다.

3. 대분류: 화면별 밀도 판단

3.1 중분류: 사용자 화면

소분류:

  • 본문 글자는 관리자 테이블보다 크게 둔다.
  • 너무 많은 필터를 한 번에 노출하지 않는다.
  • 카드형을 쓸 수 있지만 카드가 화면을 불필요하게 크게 차지하지 않게 한다.

3.2 중분류: 관리자 화면

소분류:

  • 정보 밀도, 비교 가능성, 반복 작업 속도가 우선이다.
  • 큰 hero, 장식 이미지, 넓은 빈 여백을 피한다.
  • 테이블, 검색조건, 상세보기는 같은 업무 흐름으로 이어지게 한다.

3.3 중분류: 접근성 예외

접근성 점검 페이지는 크기와 간격을 줄이지 않는다.

소분류:

  • 디자인시스템/accessibility_check.html은 변경하지 않는다.
  • .a11y-* 크기, spacing, line-height, target size를 변경하지 않는다.

4. 요약표
