# 시험 랜딩페이지 기획 프롬프트

## 1. 프로젝트 목적

시험 관련 랜딩페이지 시안을 기획한다.

이 랜딩페이지는 기존 그리너스의 운영 경험과 AITE의 미래 사업성을
함께 보여주는 것을 목표로 한다. 단순한 시험 소개 페이지가 아니라,
시험의 필요성, 신뢰성, 활용 가능성을 설득하는 페이지로 구성한다.

그리너스는 기존 시험/교육 운영 경험을 보여주는 신뢰 기반으로 사용하고,
AITE는 앞으로 소개할 핵심 시험 브랜드 또는 미래형 평가 사업으로 다룬다.

## 2. 대상 방문자

- 시험 도입을 검토하는 교육기관 또는 기업 담당자
- AI 및 언어 평가에 관심 있는 학습자
- 자격시험의 신뢰성과 활용성을 확인하려는 방문자
- 기존 시험과 AITE의 차이를 알고 싶은 방문자

## 3. 참고 사이트

### 그리너스 기존 사업

- 20년간 운영한 시험/교육 사업 참고:
  - https://timestesol.com/
- 2025년에 제작한 AITE 테스트 페이지:
  - https://aite-test.imweb.me/
  - https://aite-test.imweb.me/19

### ITT 참고

- ITT 소개 페이지:
  - https://itt.or.kr/web/itt/intro.php

ITT에서는 시험 제도의 필요성, 공신력 설명 방식, 활용 분야의 논리만
참고한다. 기관명, 자격명, 고유 문구, 법적 표현은 그대로 사용하지 않는다.

## 4. 기획 방향

랜딩페이지는 그리너스의 기존 운영 경험을 신뢰 기반으로 삼고,
AITE를 미래형 시험/평가 사업으로 자연스럽게 소개하는 흐름으로 구성한다.

핵심 방향은 다음과 같다.

- 그리너스가 오랜 기간 시험/교육 분야를 운영해왔다는 신뢰감 전달
- AITE가 앞으로 확장 가능한 새로운 시험/평가 사업이라는 점 강조
- ITT의 소개 방식에서 시험의 필요성, 객관성, 공신력에 대한 논리 참고
- 방문자가 “왜 이 시험이 필요한가”를 이해할 수 있도록 구성
- FAQ를 통해 실제 사용자가 궁금해할 내용을 랜딩페이지에 반영

## 5. 필요한 랜딩페이지 구성

다음 섹션을 포함한 랜딩페이지 구성을 제안해줘.

- Hero 섹션
- 시험 또는 평가의 필요성
- 그리너스의 운영 경험과 신뢰성
- AITE 소개
- 시험의 활용 분야
- 기대 효과
- FAQ
- 문의 또는 신청 CTA
- 푸터

## 6. 콘텐츠 작성 기준

문구는 다음 기준으로 작성해줘.

- 전문적이지만 너무 딱딱하지 않게
- 시험의 공신력과 실용성을 함께 강조
- 기존 사업의 신뢰감과 미래 사업의 확장성을 연결
- ITT의 논리는 참고하되, AITE만의 표현으로 재구성
- 랜딩페이지에 바로 넣을 수 있는 제목과 본문 형태로 작성
- 추상적인 설명보다 실제 페이지에 사용할 수 있는 카피 중심으로 작성

## 7. FAQ 상태와 목적

- 타임스통번역의 경우, Frequently의 제목은 알 수 없어서 비워져 있다.
- `resource/*.md`는 기존 사이트의 FAQ를 참고하여 정리한 자료다.
- `itt-ai-expected-faq.md`는 ITT AI 자격시험에 대한 예상 FAQ다.
- 이 자료들을 정리한 목적은 랜딩페이지에 넣을 내용을 도출하기 위함이다.

FAQ 자료는 그대로 복사하지 말고, 사용자의 궁금증 유형을 파악하는 참고
자료로 사용한다. 중복 질문은 통합하고, 랜딩페이지 방문자가 이해하기 쉬운
질문과 답변으로 재작성한다.

## 9. 추가 내용 체크

이번 산출물은 단순 독립 HTML 시안이 아니라, `layout_redesign` 폴더에
들어갔을 때 기존 `index.html`을 대체할 수 있는 수준으로 작성한다.
다만 파일 생성 위치는 `layout_redesign` 폴더가 아니라
`랜딩페이지_시안_도출/output` 폴더로 한다.

추가로 반영할 기준은 다음과 같다.

- `layout_redesign/index.html`의 헤더, 푸터, 버튼, 섹션, 카드, FAQ 등
  기존 UI 구조와 클래스 체계를 우선 활용한다.
- 별도 독립 스타일을 새로 크게 만들기보다 `layout_redesign/styles.css`의
  디자인 톤과 컴포넌트 규칙에 맞춰 작성한다.
- 파일을 `layout_redesign/index.html`로 교체했을 때 주요 링크, 공통 스크립트,
  로그인/회원가입 모달, 푸터 동작이 유지되도록 한다.
- Hero, 섹션 헤더, 카드 그리드, CTA, FAQ는 기존 `layout_redesign`의
  시각 언어와 간격을 따른다.
- 산출물에는 기존 `index.html` 대체용 HTML임을 명확히 표시한다.
- 제안안은 3개로 제한하지 않고, 방향성이 겹치지 않도록 다양한 형태로
  3개 이상 제시한다.
- Hero 섹션 카피, CTA 문구, FAQ 후보도 정해진 개수에 묶이지 않고
  실제 선택지가 충분하도록 넉넉하게 제안한다.

## 10. AI에게 요청할 산출물

위 내용을 바탕으로 다음 결과물을 작성해줘.

1. 랜딩페이지 전체 섹션 구성
2. 각 섹션별 제목과 설명 문구
3. Hero 섹션 카피 다수안
4. AITE 소개 문구
5. FAQ 8개 이상
6. CTA 문구 다수안
7. 전체 톤앤매너 제안

산출물은 3개 이상 다양한 형태로 제공한다. 랜딩페이지에 바로 적용할 수 있는 수준의 실무형 문구를 우선하며, html형태로 구성한다.
단, 최종 적용 후보는 `layout_redesign/index.html`을 대체할 수 있는 구조와
디자인 규칙을 우선한다.
